## 4. 主要发现

### AUDIT-01 — 用户界面仍直接展开技术异常文本（P1）

证据包括但不限于：

- `app/src/online/.../OnlineSettingsActivity.kt` 的模型拉取与测试失败路径直接使用
  `error.localizedMessage`；
- `MainActivity.kt`、`ModelManagementActivity.kt` 多处直接使用 `localizedMessage`；
- `ScreenTranslationService.kt` 把 `error.message` 拼接进用户可见错误；
- 当前只有 `OnlineHttpPolicy` 对部分网络错误分类，尚无跨 Activity/Service 的集中式
  `UserFacingError` 映射和显式“技术详情”边界。

影响：#68 对 DNS/TLS/HTTP/timeout/cancel 的稳定中文摘要、raw exception 仅在展开详情中
出现等条目尚未满足。异常链必须先脱敏，再允许进入技术详情；API Key、Authorization、
OCR 文本与完整响应正文禁止进入 UI、日志或测试产物。

建议：在 v2.4 #78 中建立共享 `UserFacingFailure` 分类与 Online 指标模型；随后把模型准备、
首页和服务错误迁移到同一脱敏边界。#68 在迁移和三样式渲染完成前保持开放。

### AUDIT-02 — 文档仍有旧 edition 版本身份（P1）

`README.md` 与 `docs/ARCHITECTURE.md` 仍出现 `2.0.0-lite/full/online`，与当前 Gradle
`2.3.0` 和公开 Release 不一致；README 首屏也没有 #69 要求的“哪个 APK”表格和 APK/AAB
解释。当前 preview 明确是生成图而非真机录屏。

影响：新用户可能选择错误资产，且文档身份与 `BuildConfig` 分离。#69 保持开放；版本显示应
由可检查的 Gradle/Release 数据更新，并保留签名真机演示作为独立证据。

### AUDIT-03 — v2.2.0 的代码完成与设备验收被正确分离（正向控制）

PR #82 已把 #43/#44/#45/#70/#71/#72 实现合入 `main`，`docs/ROADMAP.md` 也明确代码和
自动化通过后仍需签名 Release 与目标真机证据。GitHub 六项均保留
`status:needs-verification`，没有因为代码合并而提前关闭。

该状态应继续保持。v2.3.0 的通用耐久证据不自动覆盖模型中断恢复、fresh install、
Quick Settings Tile 或三 edition 信任中心矩阵；需逐项补齐或在后续同一签名候选中明确吸收。

### AUDIT-04 — v2.4 的四项需求目前缺少统一合同（P1）

- `SourceTextFilter` 是 whole-line nullable filter，混合中英行会整行丢弃，纯汉字日文也被
  保守丢弃；无法表达“保留目标 span、只翻译 eligible span、确定性重建”；
- `PpOcrv6Engine` 固定最长边 640 与单套阈值；`OcrEngine` 接口没有 profile/pass/budget；
- Online 已有可取消单请求、`/models` 列表和 429 bounded retry，但没有可搜索 metadata、
  严格 block-ID batch response、请求级无内容指标或 batch split 合同；
- capture/OCR/translation/overlay 的实现边界存在，但 `ImageReader`/MediaProjection 所有权
  仍直接耦合在服务路径，CI 无法注入完整 start→OCR→translate→publish→copy→stop 旅程。

这些不是单点补丁，必须先固定共享数据合同和预算，再分别接入三个 edition。
`docs/V2_4_0_DESIGN.md` 给出冻结后的实现顺序和验收矩阵。

## 6. 非真机正向控制

- Release 三版只允许 `arm64-v8a`；Online contributor 只允许 `x86_64`；
- PP-OCRv6 模型与字符表有固定 revision、字节数与 SHA-256；
- Offline trust documents 随包，Online API Key 使用 Android Keystore 加密并设置
  `FLAG_SECURE`；
- `ProtectedTextCodec` 对 URL、邮箱、日期、金额、小数与版本建立确定性 token；
- 区域路径 latest-wins/代次校验、全屏 block source-match 与 stop/close 都已有 JVM 合同；
- Release workflow 的签名 build 与 exact-byte publish 分离，公开资产来自已验收 Artifact。
